# Required tools for CommonProjectStructure

## Hints

[ScriptCollection](https://github.com/anionDevelopment/ScriptCollection) contains scripts to implement a repository-structure defined by the [`CommonProjectStructure`](<https://projects.aniondev.de/PublicProjects/Common/ProjectTemplates/-/blob/main/Conventions/RepositoryStructure/CommonProjectStructure/CommonProjectStructure.md>).
To be able to run the scripts specified by the `CommonProjectStructure` successfully some tools may be required dependent on your project.
For typically used tools the [Tools](#tools)-section contains a short description how to install them.

### Requirements

### Configuration

#### localhost.private-hosts-entry

`*.localtest.me` is a not-existing domain which can be used to host a HTTPS-server with a trusted certificate on the local development machine.
For this reason you have to add an entry like `127.0.0.1 *.localtest.me` to the hosts-file on your local development-machine.
After this the scripts inside of the code-unit can generate a certificate for the domain `codeunitname*.localtest.me` which can be used for local development-purposes.
See the [ReadMe](https://readme.localtest.me/) for more information.

### Tools

#### ar

`ar` is an archive-program.
It can be installed with `apt-get install binutils` on a Debian- or Ubuntu-system.
It can be installed using MinGW on a Windows-system.

#### coverage

[coverage](https://github.com/nedbat/coveragepy) is required to create test-coverage-reports for [python](https://www.python.org)-projects.
The package can be installed using `pip install coverage`.

#### docfx

[DocFX](https://github.com/dotnet/docfx) is a tool to generate HTML-references by markdown-files.
It is required for code-units of every type, because the reference of every code-unit is generated with it.
For .NET-code-units it can additionally generate a class-reference based on the [documentation-comments](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/documentation-comments) in the source-code.
The commandline-tool can be installed using `dotnet tool install -g docfx`.

If the reference of a .NET-code-unit is generated with a class-reference (`generate_reference(generate_class_reference=True)`; the folder `<code-unit-name>/Other/Reference/ReferenceContent/API` then contains a `toc.yml`-file generated by docfx), then ScriptCollection additionally generates a `toc.md`-file next to it after each docfx-run.
This file contains a headline, one sub-headline per namespace and a link to the corresponding docfx-file for each documented type.

#### docker

[docker](https://www.docker.com) is required to create docker-images from a dockerfile.
`scbuildcodeunits` uses it in every repository as well: the PlantUML-diagrams are rendered in a container, the secret-scan runs in a container and a container-build (`scbuildcodeunits -c`) runs the whole build in a container.
Install-instructions can be found [here](https://docs.docker.com/engine/install/).

#### docker-pushrm

[docker-pushrm](https://github.com/christian-korneck/docker-pushrm) is a commandline-tool to edit descriptions of a docker-image on [hub.docker.com](https://hub.docker.com).
ScriptCollection calls the executable `docker-pushrm` to push the `ReadMe.md` of a code-unit as description of its image.
Install-instructions can be found [here](https://github.com/christian-korneck/docker-pushrm#installation).

#### dotnet

[dotnet](https://learn.microsoft.com/de-de/dotnet/core/tools/dotnet) is the CLI-command to provide commands for working with .NET projects and run .NET applications.
Install-instructions for the commandline-tool can be found [here](https://dotnet.microsoft.com/en-us/download).

#### dotnet cyclonedx

[CycloneDX for .NET-projects](https://github.com/CycloneDX/cyclonedx-dotnet) is a tool to generate the SBOM-file `<code-unit-name>.<version>.sbom.xml` in the `BOM`-artifact for .NET-projects.
The commandline-tool can be installed using `dotnet tool install --global CycloneDX`.

#### epew

[epew](https://github.com/anionDev/Epew) is a wrapper for executing programs.
ScriptCollection uses it to run some programs (for example `npm`, `npx`, `flutter` and `openspec`); a build-step which does this fails if `epew` is not available.

#### gh

[gh](https://cli.github.com/) is GitHub's commandline-tool to interact with [github.com](https://github.com) from commandline.
The commandline-tool can be installed using `choco install gh`.
Further installation-instructions are on the [official website](https://cli.github.com/manual/installation).

#### git

[git](https://git-scm.com/) is a common version control system.

#### java

[java](https://openjdk.org/) is the commandline-tool for running [Java](https://docs.oracle.com/en/java)-programs.
ScriptCollection uses the `java` of the system to run the OpenAPIGenerator when an API-client is generated from the API-specification of a dependent code-unit.

#### npm

[npm](https://www.npmjs.com) is the package-manager of [node](https://nodejs.org/en).
The command `npm` is usually available after you have installed node.

#### openspec

`openspec` is the commandline-tool of OpenSpec.
If a repository contains `openspec/config.yaml`, then `scbuildcodeunits` uses it (via `epew`) to update the OpenSpec-instruction-files (`openspec update --force`) and to validate the specifications (`openspec validate --all --strict`).

#### pygmentize

`pygmentize` is the commandline-tool of [Pygments](https://pygments.org).
It is used to generate the diff-report of a code-unit as HTML-file.
It is installed together with ScriptCollection, because Pygments is a dependency of ScriptCollection.

#### python

[Python](https://www.python.org) is a common script-language.

#### reportgenerator

[ReportGenerator](https://reportgenerator.io/) is required to generate HTML-reports from test-coverage-reports.
The commandline-tool can be installed using `choco install reportgenerator.portable`.

#### scriptcollection

[ScriptCollection](https://github.com/anionDevelopment/ScriptCollection) is required to run the scripts (`Build.py`, etc.).
The package can be installed using `pip install ScriptCollection`.

#### sh

The shell `sh` is already pre-installed on most linux-systems.
On Windows a windows-port called `sh.exe` is contained in [git for windows](https://git-scm.com/download/win) and can be found usually in `C:\Program Files\Git\usr\bin`.

#### sn

The [Strong Name tool](https://learn.microsoft.com/en-us/dotnet/framework/tools/sn-exe-strong-name-tool) (Sn.exe) helps sign assemblies with strong names.
It is contained in the [Windows SDK](https://developer.microsoft.com/en-us/windows/downloads/windows-sdk/).

#### swagger

[Swagger](https://swagger.io) is required to generate the `APISpecification`-artifact for .NET-WebAPI-Projects.
The commandline-tool can be installed using `dotnet tool install --global swashbuckle.aspnetcore.cli`.

#### t4

[t4](https://github.com/mono/t4) is a tool to generate C#-files from [T4](https://learn.microsoft.com/en-us/visualstudio/modeling/code-generation-and-t4-text-templates)-templates.
It can be installed using `dotnet tool install --global dotnet-t4`.
It is an alternative implementation for [TextTransform](https://learn.microsoft.com/en-us/visualstudio/modeling/generating-files-with-the-texttransform-utility).

#### tar

`tar` is an archive-program.
It can be installed with `apt-get install tar` on a Debian- or Ubuntu-system.
It can be installed using MinGW on a Windows-system.

#### twine

[Twine](https://twine.readthedocs.io/en/stable/) is a utility for publishing [python](https://www.python.org) packages to PyPI and other repositories.
The commandline-tool can be installed using `pip install twine`.

#### vg2svg and vl2svg

[Vega (vg2svg) and Vega-lite (vl2svg)](https://vega.github.io/) are tools to generate chart-diagrams.
The commandline-tools can be installed using:

```sh
npm i -g vega
npm i -g vega-cli
npm i -g vega-lite
npm i -g vega-embed
```

### Tools for specific code-unit-types

The following tools are only required for code-units of the respective type.

#### C/C++-code-units

- `MSBuild`: builds the windows-target. It is located with `vswhere` (contained in every Visual-Studio-installation), so Visual Studio with the "Desktop development with C++"-workload is required for that target.
- [`docker`](#docker): builds the linux-target in a container (unless the code-unit disables that; then the linux-target is built with `/bin/sh` on a Linux-host).
- `/bin/sh`: runs the build-commands of the macOS-target (locally on macOS, otherwise on a macOS-runner, see [Remote-build](./RemoteBuild.md)).

#### Docker-code-units

- [`docker`](#docker): builds the image and generates its SBOM with the Syft-image.

#### .NET-code-units

- [`dotnet`](#dotnet), [`dotnet cyclonedx`](#dotnet-cyclonedx), [`sn`](#sn), [`swagger`](#swagger) and [`t4`](#t4).

#### Flutter-code-units

- `flutter`: resolves the dependencies, analyzes, tests and builds the app (via `epew`). The windows-, macos-, ios- and appbundle-targets are built on a remote-runner (see [Remote-build](./RemoteBuild.md), which also describes when the windows-target is built locally).

#### Go-code-units

- `go`: builds, lints (`go vet`) and tests the module.
- `gofmt`: checks the formatting.
- `cyclonedx-gomod`: generates the SBOM.

#### Maven-code-units

- `mvn`: builds, lints (checkstyle) and tests the project and generates the SBOM (cyclonedx-maven-plugin).

#### NodeJS-code-units

- [`npm`](#npm): installs the dependencies and runs the scripts of the `package.json` (via `epew`).
- `cyclonedx-npm`: generates the SBOM (via `epew`).

#### Python-code-units

- [`coverage`](#coverage) together with `pytest`: runs the tests and creates the test-coverage-report.
- `pylint`: lints the code.
- `cyclonedx-py`: generates the SBOM.

These tools are installed together with ScriptCollection, because they are dependencies of ScriptCollection.

#### Rust-code-units

- `cargo` with the subcommands `clippy`, `cyclonedx` and `llvm-cov`: builds, lints and tests the project and generates the SBOM.

#### TypeScript-code-units

- [`npm`](#npm): installs the dependencies.
- `npx`: runs the locally installed tools of the project (via `epew`).

### Tools for further functions

The following tools are not required to build a code-unit, but some functions of ScriptCollection use them:

- `openssl`: generates certificates and certificate-sign-requests (for example `scgeneratecertificateauthority`, `scgeneratecertificate` and `scgeneratecertificatesignrequest`).
- `ffmpeg` and `ffprobe`: generate thumbnails of videos (`scgeneratethumbnail`) and test-streams.
- `montage` (from ImageMagick): combines the frames of a thumbnail into one image (`scgeneratethumbnail`).
