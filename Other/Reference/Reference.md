| SEC-1  | open            | `GeneralUtilities.is_ignored_by_glob_pattern` does not reliably reject paths outside the source-directory, because the check is a plain `startswith`.                                                                                                                                                                                       | A sibling-folder with a shared prefix (for example `/folder/src2/a.txt` for the source-directory `/folder/src`) passes the check; its relative path starts with `..` and can still be matched by patterns like `*`, so files outside the source-directory can be treated as inside.                   | Former id: KI-04. | SEC-2  | open            | `scprintfilecontent` checks a different file than it reads when `-b` is not the current working-directory: a relative `-p` is resolved against `-b` for the permission-check, but the file is then read relative to the current working-directory.                                                                                          | With a base-folder other than `.` a file outside the base-folder or inside an excluded folder can be read, which bypasses the restriction (relevant for example for restricted AI-command-execution).                                                                                                 | Former id: KI-08. Category: security. With `-b .` (the default) both paths are the same. Fix: read the same resolved path which was checked. | SEC-3  | open            | The bill-of-materials of a node-codeunit is not written when one of its packages has an unsatisfied optional peer-dependency. `cyclonedx-npm` runs `npm ls --json --long --all`, npm reports an optional peer-dependency which is present in another version as `invalid` and exits non-zero, and `cyclonedx-npm` aborts on that exit-code. | The codeunit gets no BOM-artifact at all while the build still reports success, so the dependency- and vulnerability-overview of that codeunit is missing without anybody noticing.                                                                                                                   | Former id: KI-02. Category: build/BOM; classified as security-relevant because the vulnerability-overview is affected. Found in the repository AthenaTournamentManager (ATM), codeunit `AthenaWebsite`: `jsdom` (through vitest) brings `@exodus/bytes` with the optional peer `@noble/hashes` in `^1.8.0 \|\| ^2.0.0`, while `pkijs` (through `@angular-devkit/build-angular`) pins it to `1.4.0`. Fix belongs where the tool is called: `cyclonedx-npm` has `--ignore-npm-errors` for this case. The `npm install --force` of the node-codeunit-automation hides such a conflict. State-check: `TFCPS_CodeUnitSpecific_NodeJS.py` and `TFCPS_CodeUnitSpecific_TypeScript.py` still call `cyclonedx-npm` without `--ignore-npm-errors`. |
| SEC-4  | open            | `ProgramRunnerSudo.run_program_argsasarray` runs `sh -c "echo <password> \| sudo -k -S <program> <arguments>"`: the password is part of the command-line and the arguments are interpreted by the shell (only arguments with spaces are quoted).                                                                                            | The sudo-password can be read by every local user via the process-list (`ps`, `/proc/<pid>/cmdline`). Arguments or a password which contain shell-metacharacters (`;`, `$(...)`, backticks, `\|`) execute further commands with root-privileges.                                                      | Found in the security-focused bug-search. Location: `ProgramRunnerSudo.py`. Not trivial: the password should be passed via stdin to `sudo -S` and the arguments as array without a shell, which requires stdin-support of the program-runner.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| SEC-5  | open            | `scforeach` (`Executables.ForEach`) inserts the path of every iterated entry unescaped into a command which is executed with `shell=True`.                                                                                                                                                                                                  | A file-name like `a$(touch pwned)` or `x";id;"` in the iterated folder (for example a cloned or extracted untrusted folder) executes arbitrary commands. Quoting `{path}` in the command does not prevent `$(...)` or backticks.                                                                      | Found in the security-focused bug-search. Not trivial because it is an API-decision: either quote the path (`shlex.quote` on POSIX, `subprocess.list2cmdline` on Windows) or switch to an argument-array-based template.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| SEC-6  | open            | `TFCPS_RemoteBuild` extracts the result-archive which it receives from the runner with `tarfile.extractall(..., filter="fully_trusted")`.                                                                                                                                                                                                   | A compromised runner or a man-in-the-middle on an `http`-runner-url can write arbitrary files on the client (absolute paths, `..`-entries, symlinks pointing outside of the result-folder), for example into `.git/hooks`, which results in code-execution on the developer-machine or the CI-client. | Found in the security-focused bug-search. Location: `TFCPS/TFCPS_RemoteBuild.py` (`__write_result_into_the_repository`). Not changed directly because `filter="data"` rejects absolute symlinks and links which point outside of the result-folder, which can be part of a legitimate build-result; it has to be decided which entries a result may contain. The server-side extraction in `SCTaskRunnerServer.py` uses the same filter, but there the client is already authenticated and allowed to run any program.                                                                                                                                                                                                                   |
| SEC-7  | open            | Executables which are downloaded by `TFCPS_Tools_General` are not verified against a checksum, and some of them are not pinned to a version at all (TruffleHog, MediaMTX, FFmpeg and GRYLibrary always use the latest release).                                                                                                             | A compromised upstream-release or upstream-account delivers manipulated binaries which are executed by the build (supply-chain-attack); the unpinned downloads additionally make the build not reproducible.                                                                                          | Found in the security-focused bug-search. Location: `ensure_file_from_github_assets_is_available` and the download-functions of the tools in `TFCPS/TFCPS_Tools_General.py`. TLS is verified. Not trivial: the expected hashes and versions have to be pinned, and where they are stored is a design-decision.                                                                                                                                                                                                                                                                                                                                                                                                                           |
| SEC-8  | open            | The archives of the downloaded tools (JRE, TruffleHog, MediaMTX) are extracted with `tarfile.extractall` without a filter.                                                                                                                                                                                                                  | On Python 3.11 to 3.13 no filter means `fully_trusted`, so a manipulated archive (see SEC-7) can write files outside of the cache-folder.                                                                                                                                                             | Found in the security-focused bug-search. Location: `TFCPS/TFCPS_Tools_General.py`. Fix: `filter="data"`; this requires Python 3.11.4 or later, while `pyproject.toml` allows `>=3.11`, so the minimum-version has to be decided.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| SEC-9  | open            | The TLS-handshake of `SCTaskRunnerServer` is done while accepting a connection, which happens in the single thread of `serve_forever`, and the request-handler has no timeout.                                                                                                                                                              | One client which opens a TCP-connection and sends nothing blocks the accepting thread forever, before any authentication, so the runner accepts no further connections until it is restarted (denial-of-service). Without TLS every idle connection still occupies one thread forever.                | Found in the security-focused bug-search. Location: `TFCPS/SCTaskRunnerServer.py` (`run`). The obvious fix `wrap_socket(..., do_handshake_on_connect=False)` was tried and reverted: on machines where pip's truststore is injected into `ssl` (as on the development-machine of this analysis) `wrap_socket` then fails, so the fix needs an explicit handshake with a timeout in the handler-thread.                                                                                                                                                                                                                                                                                                                                   |
| SEC-10 | open            | The connection between `TFCPS_RemoteBuild` and `SCTaskRunnerServer` is not protected sufficiently: the client accepts `http`-runner-urls, the server listens on `0.0.0.0` with plain `http` when no certificate is given, and the server accepts empty credentials.                                                                         | Basic-credentials and the whole repository (including git-ignored secrets, by design) can be sent in clear text; a runner which was created with an empty username and password accepts every client which sends empty credentials and runs arbitrary programs for it.                                | Found in the security-focused bug-search. The credential-comparison was changed to the constant-time `hmac.compare_digest` directly. Rejecting empty credentials and requiring https (or allowing http only for localhost) are behavior-decisions.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| SEC-11 | open            | The environment-variables for the test of a docker-image are passed as `-e <name>=<value>` on the docker-command-line.                                                                                                                                                                                                                      | The values are written to the build-log and into the message of the exception which is raised when the image-test fails, so a secret which is passed as test-environment-variable appears in the CI-log.                                                                                              | Found in the security-focused bug-search. Location: `TFCPS/Docker/TFCPS_CodeUnitSpecific_Docker.py`. Fix: pass only `-e <name>` and give the values via `env_vars`, as `TFCPS_CodeUnit_BuildCodeUnits.py` already does; this also allows values with whitespace (see the existing TODO there).                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| SEC-12 | open            | Several secrets are passed as command-line-arguments: `docker login -p <password>`, the `pass:<password>`-arguments of openssl, `dotnet nuget push --api-key`, `dotnet nuget add/update source --password` and the `--password`-arguments of CLI-commands like `scaddimagetocustomregistry`.                                                | The secrets can be read by every local user via the process-list and the CLI-arguments end up in the shell-history. `docker_login` additionally splits a password which contains a space into several arguments.                                                                                      | Found in the security-focused bug-search. The leaks into the build-log and into exception-messages were fixed directly (masking for openssl, nuget push, 7z and the NuGet-source-password; twine-credentials are passed via environment-variables). Not trivial: passing the secrets via stdin (`--password-stdin`), environment-variables or files requires API-changes.                                                                                                                                                                                                                                                                                                                                                                |
| SEC-13 | open            | `ScriptCollectionCore.restore_filemetadata` joins the paths from the metadata-file with the target-folder without checking that the result stays inside the folder.                                                                                                                                                                         | A manipulated metadata-file with an entry like `../../etc/shadow;f;attacker:attacker;777` changes owner and permissions of files outside of the folder, and `d`-entries create folders outside of it.                                                                                                 | Found in the security-focused bug-search.
