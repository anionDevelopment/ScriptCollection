# Release notes

## Changes

- The rendering of plantuml-diagrams was moved from `TFCPS_Tools_General` into the new class `PlantUMLRenderer`
- PlantUML is not downloaded onto the executing machine any more. The diagrams are rendered in the image which a repository declares as `PlantUML` in `.ScriptCollection/OCIImages/ImageDefinition.csv` (for example `PlantUML;plantuml/plantuml;1.2026.8`), which contains plantuml, java, Graphviz and the fonts. The declared tag alone therefore determines what a diagram looks like
- Fixed that plantuml could not lay out component- and class-diagrams at all: the image which was used before (`Java;eclipse-temurin`) contains no Graphviz, so such a diagram was rendered as a placeholder saying "Cannot find Graphviz"
- Fixed that plantuml-diagrams could not be rendered when the build itself runs in a container whose docker-socket is forwarded to the daemon of the host (for example a build in the SCBuilder-image): the rendering-container is a sibling-container there, so a bind-mount of a path of the build-container was resolved by the daemon of the host, where that path does not exist. The volumes of the own container are shared with the rendering-container now
- Before rendering, the reachability of the docker-daemon is checked and the used image is pulled explicitly, so an unreachable daemon is reported as the infrastructure-problem it is instead of looking like a broken diagram
- Removed, because the image provides all of it: `download_plantuml`, `ensure_plantuml_is_available`, `get_plantuml_version`, `get_default_plantuml_version`, the plantuml-entry of `scdownloadcachabletools`, the version-pin `Other/Resources/Dependencies/PlantUML/Version.txt` and the DejaVu-fonts bundled with the package
- Moved the determination of the own container-id into `ScriptCollectionCore.get_own_container_id`, because the diagram-rendering and the secret-scan both need it

## Migration

Every repository has to replace the image-entry which it declared for the diagram-rendering by `PlantUML;plantuml/plantuml;1.2026.8` in `.ScriptCollection/OCIImages/ImageDefinition.csv`; the entry `Java;eclipse-temurin;...` is not used any more. The committed diagram-SVGs change once, because they are rendered with another plantuml-version now.
