# Release notes

## Changes

- `TFCPS_CodeUnitSpecific_Flutter_Functions.build`'s `windows`-target now falls back to a local `flutter build windows` when running on Windows and no remote-build-runner is configured, instead of failing. When a runner is configured, the build is still delegated to it as before, to keep the uniform build environment. Added `TFCPS_RemoteBuild.has_any_runner_configured` to support this.
- `TFCPS_CodeUnitSpecific_Flutter_Functions.build` now publishes a `BuildResult_SourceCode` copy of the `SourceCode`-artifact when `targets` is empty, so a pure Dart/Flutter library codeunit (no platform target, e.g. a domain-logic codeunit consumed only as source) satisfies `TFCPS_CodeUnit_BuildCodeUnit.build_codeunit()`'s generic `BuildResult_.+`-artifact requirement. Previously such a codeunit failed with "does not contain an artifact which matches the name 'BuildResult_.+'" the moment it went through the full `scbuildcodeunits`-pipeline.
