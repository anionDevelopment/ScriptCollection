# Release notes

## Changes

- Implemented the update of the default-tags in `.ScriptCollection/OCIImages/ImageDefinition.csv` (`TFCPS_Tools_General.update_dependent_oci_images`) and of the images in docker-compose-files (`scupdateimagesindockercomposefile`), which only logged warnings without reason before.
  - The tags of an image are read by the new `OCIRegistryClient` using the OCI-distribution-api, so docker-hub, ghcr.io, quay.io, mcr.microsoft.com and custom registries are supported. Credentials which are defined for a registry are used, otherwise the registry is accessed anonymously.
  - An image-handler is selected by the image-name and the format of the current tag. A tag consists of an optional prefix "v", a numeric version and an optional suffix (for example "13.4-slim" or "v1.62.1-noble"); only tags with the same prefix, suffix and amount of version-parts are candidates for an update.
  - The tags of GitLab CE/EE are recognized, but their update is not implemented yet because it has to respect the required upgrade-stops of GitLab.
  - The warning for an image without custom registry names the registries-file in which the registry has to be defined.
