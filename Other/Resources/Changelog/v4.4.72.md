# Release notes

## Changes

- Implemented the update of the default-tags in `.ScriptCollection/OCIImages/ImageDefinition.csv` (`TFCPS_Tools_General.update_dependent_oci_images`) and of the images in docker-compose-files (`scupdateimagesindockercomposefile`), which only logged warnings without reason before.
  - The tags of an image are read by the new `OCIRegistryClient` using the OCI-distribution-api, so docker-hub, ghcr.io, quay.io, mcr.microsoft.com and custom registries are supported. Credentials which are defined for a registry are used, otherwise the registry is accessed anonymously.
  - An image-handler is selected by the image-name and the format of the current tag. A tag consists of an optional prefix "v", a numeric version and an optional suffix (for example "13.4-slim" or "v1.62.1-noble"); only tags with the same prefix, suffix and amount of version-parts are candidates for an update.
  - The tags of GitLab CE/EE are recognized, but their update is not implemented yet because it has to respect the required upgrade-stops of GitLab.
  - The warning for an image without custom registry names the registries-file in which the registry has to be defined.
- Improved `reclaim_space_from_docker` (`screclaimspacefromdocker`):
  - Fixed `screclaimspacefromdocker` which always failed because `-v` was used for `--removevolumes` and for `--verbosity`.
  - Removed the parameter `remove_volumes` (`--removevolumes`). Unused anonymous volumes are now always removed.
  - Added the parameter `remove_named_volumes` (`-n/--removenamedvolumes`) which also removes unused named volumes (since docker 23 `docker volume prune` only removes anonymous volumes).
  - Unused networks are removed when containers are removed.
  - Dangling images (untagged leftovers of builds) are always removed.
- Added the codeunit-type for native android-apps (java or kotlin) built with gradle (`ScriptCollection.TFCPS.Android.TFCPS_CodeUnitSpecific_Android`).
  - All gradle-tasks run with the gradle-wrapper of the project on an android-runner (SCTaskRunnerAndroid), because the android-sdk is not part of SCBuilder.
  - The build produces the app-bundle (`BuildResult_AAB`), the apk (`BuildResult_APK`) and the SBOM (cyclonedx-gradle-plugin). The testcases run with `createDebugUnitTestCoverageReport`, the linting with `lintDebug`.
  - The version of the project is written into `versionName` and `versionCode` (`<major>*1000000+<minor>*1000+<patch>`) of the `build.gradle`.
  - The dependencies and the plugins which are declared with an explicit version in the `build.gradle` can be updated.
  - Visual-regression-tests (`run_visual_regression_tests`): screenshots captured by roborazzi (rendered by robolectric) are recorded into respectively verified against `Other/Resources/VisualRegressionBaselines` on the android-runner, so the baselines are reproducible locally and in the build-pipeline. The screenshots of failed comparisons are preserved in `Other/Artifacts/VisualRegressionTestFailures`.
  - A dependency-update writes the version in the format in which it is published (for example `4.18` instead of `4.18.0`).
- The common tasks of a rust-codeunit (`TFCPS_CodeUnitSpecific_Rust.do_common_tasks`) also update the `Cargo.lock` next to the `Cargo.toml` (`ScriptCollection.TFCPS.Rust.CargoLockFile`), so that a build with `--locked` does not fail after a version-change.
  - The version of every local package (the project itself and its direct and transitive path-dependencies, for example the copies of dependent codeunits in `Other/Resources/DependentCodeUnits`) is set to the version which its `Cargo.toml` declares.
  - The lock-file is edited without cargo and without network-access; all other lines and the line-endings are preserved, and running it again does not change anything.
