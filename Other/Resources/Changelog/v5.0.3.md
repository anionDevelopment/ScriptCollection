# Release notes

## Changes

- `GeneralUtilities.arguments_to_array` (and therefore `run_program`, `run_program_async` and `run_command_in_folder`) keeps a part of the argument-string which is enclosed in double-quotes in one argument, even if it contains whitespaces; the double-quotes themselves are removed (so `commit -m "my message"` results in the arguments `commit`, `-m` and `my message`). Before, the argument-string was split at every single space, so quoted values were split into several arguments which still contained the double-quotes, and multiple spaces resulted in empty arguments. Multiple whitespaces between arguments are now treated as one separator, an explicitly quoted empty string (`""`) results in an empty argument, single-quotes and backslashes have no special meaning, and an unclosed double-quote raises a `ValueError` (finding SEC-17, partially fixed).
- New commands `scinitencryptedcontainerinrepo`, `scdecryptinrepo` and `scencryptinrepo` (implemented in `EncryptedContainerInRepository`) to keep sensitive data as AES-256-GCM-encrypted container-files in a repository, defined in `.ScriptCollection/EncryptedFolders.csv` (columns `Name;Target`); the container-files are stored as `.ScriptCollection/SensitiveDataContainer/<Name>.bin`. See article "Encrypted containers in a repository". `cryptography` is now a direct dependency.
