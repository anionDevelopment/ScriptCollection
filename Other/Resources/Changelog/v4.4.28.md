# Release notes

## Changes

- Fixed a race-condition which could make any program-call (`run_program`, `run_program_argsasarray` and everything which is based on them) return an empty stdout and stderr although the program produced output and terminated with exitcode 0. The reading of the output stopped as soon as the process was terminated and the internal queues were empty, without checking whether the reader-threads had transferred the content of the pipes into those queues at all, so the output of short-running programs could be discarded completely. The problem occurred mainly on linux and under load, for example in a ci-pipeline
