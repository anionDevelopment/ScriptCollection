# Release notes

## Changes

- Fixed program-runs with a program-runner which returns an already terminated popen-object (for example `ProgramRunnerSudo` or a runner which executes programs on a remote machine): the output of the program was lost, because `SudoPopen` provided stdout and stderr as bytes, which can not be read line by line. `SudoPopen` now provides them as text-streams and has the method `kill`.
- `ScriptCollectionCore.run_program_argsasarray` raises an error if reading the output of a program fails, instead of returning the program-run as a successful run without any output.
- `ScriptCollectionCore.list_content`: if listing the content of a folder on a not-local target fails, the raised error now names the folder, the exitcode and stderr (before, the message wrongly referred to checking whether a file exists).
- `scbuildcodeunits`: if a repository uses openspec (`openspec/config.yaml` exists) but openspec is not initialized in it yet (no openspec-skill exists), `openspec init` is run immediately before `openspec update --force`. Before, `openspec update` silently did nothing in such a repository, because it only updates tools which are already set up.
- `scbuildcodeunits`: the project-linting checks the file `.well-known/security.txt` and shows a warning for every failed check: the file does not exist, the file is not signed or its PGP-signature is not valid, the `Expires`-field is missing, expired or valid for less than 3 months. If an internet-connection is available it is also checked whether the `Canonical`- and `Encryption`-URLs are reachable. The signature is verified with `gpgv` against the public key which is downloaded from the `Encryption`-URL (so only the validity of the signature is checked, not whether the key is trusted, and the check does not depend on the keyring of the machine which runs the build).
- `ProgramRunnerPopen` replaces bytes in the output of a program which are not valid in the used encoding, instead of losing the remaining output of the program (for example `gpgv` writes a name with an umlaut in latin-1).
- Declared `packaging` and `requests` as dependencies of the pip-package, because ScriptCollection imports both directly; before, they were only installed transitively by other dependencies.
- Project-linting: fixed typos and translated the remaining German comments into English.
- Breaking change: renamed public names with typos: `VersionEcholon` to `VersionEchelon` (including all `echolon`-parameters and the methods `get_default_echelon_for_update` and `update_dependencies_with_specific_echelon`), `PrintCurrecntWorkingDirectory` to `PrintCurrentWorkingDirectory`, `DownloadCachableTools` to `DownloadCacheableTools`, `download_all_cachable_tools` to `download_all_cacheable_tools`, `is_runnning_in_container` to `is_running_in_container`, `suport_information_exists` to `support_information_exists`, `copy_licence_file` to `copy_license_file` and the parameters `resurse_submodules` (of `git_push`) to `recurse_submodules` and `target_envionment_type` to `target_environment_type`. The CLI-command `scdownloadcachabletools` is renamed to `scdownloadcacheabletools` and the options `--echolon` and `--image-echolon` of `scupdateimagesindockercomposefile` are renamed to `--echelon` and `--image-echelon`.
- Added `TFCPS_Tools_General.update_dependencies_of_package_json_file`, which updates the dependencies and dev-dependencies of a package.json-file which does not belong to a codeunit (for example the one in the repository-root which declares husky).
- Added `Other/Scripts/UpdateDependencies.py`, which `scupdatedependencies` runs automatically and which updates the dependencies of `package.json` to their latest versions; declared husky as pinned dev-dependency in `package.json`.
- Fixed the URLs in `.well-known/security.txt` (the signature of the file has to be renewed).
