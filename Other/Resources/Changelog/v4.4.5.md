# Release notes

## Changes

- update for checking python codeunits
- added the commandline-tool "scupdatedependenciesc", which updates the dependencies inside the SCBuilder-image, and the parameters "-c"/"--runincontainer" and "-b"/"--basemountfolder" for "scupdatedependencies". This is the same pair as "scbuildcodeunits" and "scbuildcodeunitsc". The whole update runs in the container and not only the codeunit-builds which it triggers, because the update hands a hook-object to the build of the codeunits and an object can not be passed to a program through commandline-arguments, so a containerized inner build would build without updating anything. Only the parameters which "scupdatedependencies" really accepts are passed into the container: it has no equivalent of the pre-merge-, assert-no-new-changes-, ready-to-merge- and fastlane-flags of "scbuildcodeunits"
- the logic which runs a commandline-tool of this product inside the SCBuilder-image (the mounts, the environment-variables which are declared as required, the preparation-hooks and the resolving of the folders inside the container) is shared between the build of the codeunits and the update of the dependencies now instead of belonging to the build alone
