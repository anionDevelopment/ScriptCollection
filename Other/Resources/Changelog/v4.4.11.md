# Release notes

## Changes

- a dotnet-codeunit has one lock-file per project again ("packages.lock.json") instead of one per runtime: the projects
  state the runtimes they are built for, the build restores once without naming a runtime and builds every runtime from
  that result. The build, the linting, the testcases, the generation of the reference and an ide therefore all read and
  write the same file, so a lock-file which one of them creates does not let the next one fail anymore
- a project which is built for a runtime it does not state is reported with a message which names the declaration it is
  missing, instead of failing later with NETSDK1047, which names the assets-file and not the reason. The format-check
  of a project-file of a dotnet-codeunit requires the declaration as well, directly below the target-framework
- the hints of the codeunit state how the lock-file of a dotnet-codeunit is used: how it is updated and which errors of
  a restore in locked mode mean what
