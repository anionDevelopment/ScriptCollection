# Release notes

## Changes

- added the possibility to declare environment-variables which are additionally required for every codeunit-build on a specific machine, regardless of what a repository declares in its `ProductInformation.xml`: they are declared (name-only, one per line) in `<configuration-folder>/TFCPS/AdditionalRequiredEnvironmentVariables.txt` (see `TFCPS_Tools_General.get_additional_required_environment_variable_names_for_this_machine`). This lets machine-local tooling (for example a custom pre-codeunit-build-script which is specific to one developer's machine) declare the environment-variables it needs without forcing every repository which happens to be built on that machine to declare them too - a repository must not have to know about a specific developer's machine-local tooling. The file is optional; if it does not exist nothing changes.
- for a locally started build-container (`scbuildcodeunitsc`), the whole folder `<configuration-folder>/TFCPS/CustomScriptsForContainer` is now mounted into the container (at the same location the pre-codeunit-build-hook `CustomPreCodeUnitBuildScriptInContainer.py` was mounted at before) instead of only that single file. This lets that hook start a sibling script placed next to it in the same folder, so the hook itself can stay independent of a package it only installs while the actual preparation-logic (which needs that package) lives in the sibling script. The mount is writable (not read-only), because the scripts in that folder may also use it as their own download-cache-folder.
